**這些結論的共同限制**：資料庫層是在 PGlite（WASM 版 PostgreSQL 18）與自製模擬器上驗證，不是真正的 Supabase。真實的 PostgREST、GoTrue、閘道、CORS、email、同時寫入的鎖競爭都**未驗證**，這正是下一階段要做的事。

## 4. 尚存的風險

| #   | 風險                       | 影響                                                                                                                | 建議                                                                  |
| --- | -------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| R1  | **程式碼只在這台電腦**     | 電腦壞掉就全沒了。Git 沒有 remote                                                                                   | 推到私有 GitHub。Cloudflare 自動部署也需要它                          |
| R2  | **Free 方案沒有自動備份**  | 誤刪或 migration 出錯時，Supabase 救不回來。App 的 JSON 匯出是手動的                                                | 見第 5 節                                                             |
| R3  | **還原不是原地還原**       | 匯入一律建立新副本，不覆蓋也不合併。資料還在時匯入會變成兩份，要手動刪舊的                                          | 記在還原流程裡；要原地還原得用 `db dump`                              |
| R4  | 閒置 7 天專案暫停          | 放假回來 App 連不上，要到 Dashboard 恢復（文件）。錯誤畫面未實測                                                    | 測試計畫 O5。資料重要就升級 Pro（約每月 25 美元，以官網為準）         |
| R5  | 大檔匯入可能逾時           | 依文件 `authenticated` 預設 statement timeout 約 8 秒。逾時會整批失敗，不會只匯入一半（讀碼），但大備份可能還原不了 | 測試計畫 B5 量測。不夠就分批或調高 timeout                            |
| R6  | 跨裝置同時編輯是後寫者勝   | 兩台同時改同一段描述，先送出的會被蓋掉且沒有提示（D15、D26）                                                        | 單人使用機率低，先接受                                                |
| R7  | 關分頁時正在送的寫入       | 請求可能被瀏覽器中斷。有提示視窗，重新整理可找回，關分頁不行                                                        | 測試計畫 S7 實測後再決定是否加 `keepalive`                            |
| R8  | 沒有錯誤監控               | 正式環境出錯時，只有使用者畫面看得到                                                                                | 單人使用可先不做；之後可評估免費額度的錯誤追蹤（要先檢查 CSP 與隱私） |
| R9  | 忘記密碼信受內建寄信限制   | 依文件每小時 2 封，且只寄給專案成員                                                                                 | 把自己設為專案成員即可，有需要再設 custom SMTP                        |
| R10 | Session 存在 localStorage  | supabase-js 的標準做法；XSS 可讀到。CSP 已擋掉外部腳本                                                              | 接受                                                                  |
| R11 | 載入不是單一交易           | 6 張表平行讀取，另一台同時改動時可能短暫不一致，下次更新就修正（讀碼，未觀察）                                      | 接受                                                                  |
| R12 | 測試環境沒有真實瀏覽器廣度 | 自動化只跑 Chromium。Safari、Firefox、真實輸入法都未驗證                                                            | 測試計畫 S5、W4                                                       |

本機環境也有兩點要注意：磁碟只剩約 4 GB，Docker 沒有在跑，所以這次**沒有**用 `supabase start` 在本機跑整套 Supabase（映像要好幾 GB）。另外長時間測試時不要闔上筆電：有一次回歸因為闔蓋睡眠而失效（12 個假失敗），已重跑。
