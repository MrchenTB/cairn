## 3. 自動儲存的實際互動規則

### 各欄位

| 欄位                    | 何時儲存                                                | 無效或失敗時                                      |
| ----------------------- | ------------------------------------------------------- | ------------------------------------------------- |
| Status、Priority、Phase | 選了就存                                                | 畫面回到舊值，Footer 顯示哪個欄位沒存，可 Retry   |
| Start、Due              | 選了就存，兩個日期一起送                                | 無效日期選不到；失敗同上                          |
| Title                   | Enter、失焦、關閉                                       | 空白：退回已存標題並提示。超過 500 字：保留、不送 |
| Description             | 停止輸入 2 秒、失焦、關閉、分頁隱藏；連續輸入最長 10 秒 | 超過 10,000 字：保留、不送                        |
| Add subtask             | Enter；關閉時若還有字，自動新增並提供 Undo              | 失敗時 store 的 toast 提供 Retry                  |

### 離開

| 動作                              | 結果                                                        |
| --------------------------------- | ----------------------------------------------------------- |
| Esc、X、Done、點遮罩、⌘↵          | 有效文字交給 store，立刻關閉，不等網路、不詢問              |
| 從父任務開啟的子任務，做上述動作  | 回到父任務，再做一次才關閉                                  |
| 直接開啟的子任務（列表、連結）    | 直接關閉，沒有父任務可回                                    |
| 瀏覽器上一頁、點連結、⌘K New task | 有效文字送出；存不了的留在草稿，並提示「Unsaved text kept」 |
| 文字過長時關閉                    | 對話框：Keep editing／Discard text，不會默默丟棄            |
| 組字被打斷的文字還在時關閉        | 留在 Modal，提示先按 Save 或 Discard                        |

### 日期與排程

- **Manual**：直接寫入。衝突改由 Modal 內的橫幅提示，不再出 toast，否則先改開始日、再改截止日時會閃過一則馬上過時的警告。
- **Auto**：需要移動其他任務時先跳預覽。Apply 整批寫入；Cancel 不寫入，日期回到已存值，並顯示「Dates not changed.」。
- 每次寫入出一個可 Undo 的 toast。日期之後又被改過時，Undo 會說「Can’t undo」，不會蓋掉新資料。
- 要把兩個日期都往後移，得先改截止日（與 List 相同）。

### 儲存狀態

| 狀態                         | 何時出現                                     |
| ---------------------------- | -------------------------------------------- |
| `Pending changes`            | 文字等待送出超過 1 秒，打字時不會閃          |
| `Saving…`                    | 寫入超過 0.4 秒才顯示，出現後至少停留 0.6 秒 |
| `Saved`                      | 寫入結束後停留 2 秒，然後回到時間戳          |
| `Couldn’t save 欄位 · Retry` | 失敗時立即顯示，直到解決                     |
| `Offline`                    | 雲端模式離線時                               |
| `Not saved`、`Unsaved text`  | 文字無效；有恢復的文字等待決定               |

失敗的 toast 會寫出任務與欄位，例如 `Couldn't save the title of “Plain task”`，並提供 Retry 與 Open。Toast 消失後，側邊欄仍會列出未存的文字。

## 4. IME 測試結果

測試方式：透過瀏覽器除錯介面（CDP）送出與真實輸入法相同的事件序列。**不是真的輸入法軟體。**

| 情境                                 | 結果 | 依據                                                                     |
| ------------------------------------ | ---- | ------------------------------------------------------------------------ |
| 注音：標題組字、Enter 選字           | 通過 | 選字的 Enter 寫入 0 次；再按一次真正的 Enter 才寫入 1 次，內容為「專案」 |
| 注音：描述組字中等待超過 debounce    | 通過 | 等 2.6 秒寫入 0 次，sessionStorage 也沒有注音；選字後才計時並寫入 1 次   |
| 日文：假名逐步增長、轉換、確定       | 通過 | 組字中寫入 0 次；失焦後寫入 1 次，內容為「漢字に」                       |
| Safari 事件順序（先 compositionend） | 通過 | 模擬順序，後面的 Enter 不算存檔                                          |
| Esc 取消組字                         | 通過 | Modal 不關閉，原文字保留（Chrome 與 Safari 順序）                        |
| 組字中點別處、點 Done                | 通過 | 見下方                                                                   |
| 回應在組字途中抵達                   | 通過 | 文字不跳、不重複，游標位置正確                                           |

**測試中發現並修正的重要問題**：組字中焦點離開時，Chromium 會把注音原樣定案成文字，一開始實測 `Plain taskㄇㄚˇ` 真的被寫入資料。`compositionend` 分不出這是使用者選字還是瀏覽器強制結束，所以現在偵測組字期間的點擊與失焦：被打斷的文字**不寫入**，留在欄位並提示，由使用者選 Save 或 Discard。切換視窗與分頁隱藏也適用同樣原則。

## 5. 資料失敗與復原測試

| 情境                           | 結果 | 行為                                                                |
| ------------------------------ | ---- | ------------------------------------------------------------------- |
| 寫入失敗                       | 通過 | 文字留在欄位；訊息指出任務與欄位；Footer 或 toast 的 Retry 都能存回 |
| 失敗後繼續打字                 | 通過 | 舊 Retry 立刻撤回，不會用舊文字蓋掉新文字                           |
| 失敗後把文字打回原值           | 通過 | 同樣撤回。這種情況不產生寫入，所以需要新增撤回動作                  |
| 儲存中關閉，之後才失敗         | 通過 | 關閉不等待；toast 的 Open 帶回文字；側邊欄持續列出                  |
| 重新整理後恢復失敗的文字       | 通過 | 文字回到欄位，**不會自動寫入**，由使用者選 Save 或 Discard          |
| 重新整理後資料已被別處改過     | 通過 | 舊文字**不會蓋在新值上**，改為提示，由使用者決定                    |
| 回應遺失但其實已存好           | 通過 | 比對後自動清除，不會誤報失敗                                        |
| 還在等待送出的文字遇到重新整理 | 通過 | Local 模式在頁面離開時送出                                          |
| 多欄位部分失敗                 | 通過 | 成功的欄位留著，失敗的欄位各自標示                                  |
| 第二個帳號登入同一分頁         | 通過 | 前一帳號的文字未經讀取就刪除                                        |
| 主動登出                       | 通過 | 先送出能送的，確認框寫出會遺失幾筆，登出後刪除                      |
| 刪除任務時還有未送文字         | 通過 | 文字一起丟棄，不會對已刪任務送更新                                  |

sessionStorage 只是這個分頁的安全網，**不是永久備份**：關閉分頁就消失，也不跨裝置。

## 8. 尚存風險與限制

| 風險                                 | 影響                                                                                       | 建議                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------- |
| 真實 Supabase 未驗證                 | 真實延遲、權限與斷線行為只有模擬                                                           | 部署後依 `docs/deployment.md` 驗收      |
| 真實輸入法與 Safari、Firefox 未驗證  | 各瀏覽器在失焦時 `compositionend` 的先後順序可能不同                                       | 用真的注音在 Safari 走一次              |
| 跨裝置仍是欄位層級的後寫者勝         | 兩台裝置同時改同一段描述，後送出的蓋掉先送出的，沒有提示（重新整理恢復時才會比對）         | 需要 RPC 或 migration，依指示這次沒有做 |
| 雲端模式關分頁時可能來不及送出       | 頁面離開時的請求可能被瀏覽器中斷。有提示視窗；重新整理可由 sessionStorage 找回，關分頁不行 | 未實測；可評估 `keepalive`              |
| 屬性與日期的失敗不跨重新整理         | Status 等失敗後重新整理就消失（重選即可）                                                  | 刻意的取捨（D28）                       |
| 關閉後才失敗的 Add subtask           | 只能靠 store 的 Retry，重新整理後不會恢復                                                  | 可之後納入草稿                          |
| 組字被打斷後第一次點 Done 可能沒反應 | 提示出現讓 Footer 下移，放開滑鼠時已不在按鈕上；提示本身會說明狀況                         | 影響很小，再點一次即可                  |
| 離線時屬性晶片仍可點                 | 會失敗回滾並提供 Retry，與 List、Board 行為一致（D30）                                     | 若想改成離線時停用，告訴我              |
| 大量文字                             | 每次輸入都同步寫 sessionStorage（最多約 10,000 字），在一般裝置上未觀察到問題，但未量測    | 有感時再加節流                          |
