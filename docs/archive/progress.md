# Cairn 進度與驗收報告（版本 1.0.0，2026-11-06）

> 上線準備度與真實雲端驗收的最新狀態，見 [`production-readiness.md`](../production-readiness.md)。

**一句話現況**：PRD 要求的功能都已實作，並在本機模擬環境通過自動化測試；但「雲端同步（驗收 13）」與「真實 Supabase 的登入與權限（驗收 1、16 的雲端部分）」還沒有在真實服務上驗證過，必須由你註冊帳號、部署後親自確認，確認之前不能算完成。

本文件依 PRD §10 分成三種狀態。所有結論都來自最終 QA 紀錄與實際跑過的測試；查不到依據的項目一律標示「未驗證」。

## 4. QA 找到並修好的重要問題

QA 分多個範圍反覆測試（資料、雲端、輸入法、時區、甘特圖、效能、無障礙、安全、使用者旅程等），共找到 2 個嚴重（會遺失資料）與多個重要問題，全部已修正並補上測試。以下用白話說明。

**嚴重（會遺失資料）**

- **刪除任務時，把別處新增的子任務一起刪掉。** 在過期的分頁或另一台裝置上刪除一個任務，會默默連同你剛在別處新增的子任務一起刪除。
- **兩個標題相同的任務，第一個建立失敗後被悄悄撤回。** 資料就這樣不見，沒有任何提示。

**重要**

- 寫入失敗後的重新整理，被後來的寫入丟掉而沒有重做。
- 對失敗的刪除按 Retry，會連失敗之後才新增的資料一起刪掉。
- 匯入大型備份會讓分頁凍結（原因是演算法在依賴線很多時變慢）。
- 登入失效或被伺服器拒絕時，畫面仍默默顯示舊資料；重新登入後畫面也沒有更新。
- 伺服器暫時忙碌（HTTP 429 或 500）時，App 把你登出了，其實 session 並沒有被拒絕。
- 有失敗的寫入等著 Retry 時，被拒絕的背景更新沒有重新檢查登入狀態。
- 建立專案、階段、里程碑失敗後，按「Try again」再加上 Retry，會存成重複的資料；Chrome 在斷掉的連線上自動重送建立請求時，也可能存成重複資料。
- 用瀏覽器「前進」重新打開的任務視窗關不掉；上一頁／下一頁與任務視窗的歷史紀錄互相打架。
- 中文輸入法：選字過程中按 Esc 會關掉專案或階段對話框、時區選單，或清掉 Projects 篩選框；Safari 上確認選字的 Enter 可能直接送出表單。
- 刪除任務後立刻按 Cmd/Ctrl+K，搜尋框的焦點會被延遲的焦點歸還搶走（約 200 ms 內，電腦忙碌時更久），剛打的字進不去。
- 日期為 9999 年時，Gantt 與 Timeline 在月視圖當掉；拖曳時用滾輪或按 Today 會讓預覽停在舊日期。
- 長清單（900 列）因為每列沒有隔離重繪範圍，頁面非常肥大（約 3.5 萬個節點）。
- 打開排程預覽後切到其他分頁修改再切回來，按 Apply 會用過期資料蓋掉修改；現在切回分頁會立刻重新讀取。
- 資安檢查（`.agent-notes/qa2-security.md`）：正式版每次載入都觸發 CSP 的 eval 違規；環境變數被整批寫進程式碼，若誤放 service role key 會一起外洩。現在是依名稱讀取，且 build 遇到 secret key 會直接中止。

另外有多項較小的修正（排版溢出、提示文字、All Tasks 分頁名稱等），完整清單見 `.agent-notes/qa2-*.md`。

## 5. 本機模擬環境能證明與不能證明什麼

雲端相關的自動化測試（`npm run test:cloud`、`tests/db`）跑在本機模擬的「假 Supabase」上（`tests/cloud-sim/`，詳見該資料夾的 README）。

**能證明**

- 真實的 App 與真實的 `@supabase/supabase-js` 透過 HTTP 與真實的 migration 溝通，資料庫是真實 Postgres 引擎（PGlite）。
- RLS、權限、trigger、RPC 都以 `anon` 或 `authenticated` 角色執行；模擬器不替 App 過濾資料，對照實驗證實：關掉 RLS 後同一個請求就會讀到別人的資料，所以 RLS 確實有在擋。
- 不支援的請求會直接讓測試失敗，新的請求格式不會悄悄漏掉。
- 斷線、500 錯誤、閘道回傳網頁、逾時、回應遺失、請求被重送，App 都誠實處理。

**不能證明**

- migration 在你的 Supabase 專案上能成功套用（版本與預設權限是否相同）。
- 真實 GoTrue（登入服務）與 PostgREST 的行為；狀態碼與錯誤訊息是依文件寫的，不是錄自真實伺服器。
- Supabase 的閘道、CORS、TLS、請求大小與頻率限制。
- 真實的 email 寄送、Site URL 與 Redirect URL 設定、密碼強度、CAPTCHA、MFA 等選項。
- 非對稱 JWT 金鑰（模擬器只用 HS256）。
- 真實的同時寫入：PGlite 只有一條連線，請求一個接一個，鎖的競爭沒有發生過。
- 兩台實體電腦。兩個瀏覽器分頁只是替代。

### 6.3 規模與效能

| 項目                                | 實際影響                                                                                                                                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| List、Board 沒有虛擬捲動（D21）     | 單一專案 900 個頂層任務時，List 首次繪製約 930 ms、Board 約 570 ms、拖曳起手約 147 ms（超過 100 ms 目標但低於 300 ms）。3,000 個任務在負載高的開發伺服器上約 10 秒。個人專案遠低於此  |

| supabase-js 在本機模式也載入（D23） | 多約 165 KB（gzip）；正式使用是雲端模式，無影響                                                                                                                                       |
| 極端日期（D18）                     | 日期可用 0001–9999。同一專案日期相差超過約 2,550 年（Day，實測）或約 5,700 年（Week，計算推得）時長條會被夾在邊界。日期只能用日曆選取，需點數千次或手改備份檔才會碰到；當掉的問題已修 |

### 6.5 小瑕疵與未觀察

- 輸入法啟用而游標不在輸入框時，單鍵快捷鍵（如 `c`）可能不會觸發。依程式碼推論，未實際觀察；Cmd/Ctrl+K 不受影響。
- 拖曳 Gantt 長條時按 `c` 或 `?` 會開啟對話框，拖曳仍繼續並在放開時提交。無害且不太可能發生。
- 把連線拖到里程碑菱形上，什麼都不會存、也沒有訊息（不是假成功）。
- 日期相同的里程碑與同名排序依瀏覽器語系的預設排序，不同語系的順序可能不同（僅外觀）。
- 匯入檔案格式錯誤時，訊息可能是技術文字（如 `projects[0].color: Invalid option`）。內容正確、安全失敗；上線畫面未重新確認。
- 開機畫面（AppSplash）的第一瞬間畫面、Board 卡片焦點框的截圖，沒有另外檢視（焦點順序已有自動化檢查）。
- 排程套用被拒絕後，「Refresh and try again」之後的重試流程未檢查（拒絕本身是整批取消，已測）。
- 刪除任務後馬上開搜尋時，第一次按 Esc 沒有關閉視窗：修復焦點問題前出現過 2 次，修復後連跑 160 次未再出現，但確切機制沒有完全證實。多按一次 Esc 即可關閉。
- Gantt 階段與父任務的彙總括號在放開後才更新，拖曳中不更新（僅視覺）。
